# Clipboard (`omarchy.clipboard`) → macOS

**Status: partial.** Everything works except persistence across Hammerspoon reloads (removed on
purpose for privacy) and "open" for plain text. See Gaps below.

## What it does
A clipboard manager overlay. It records every copy (text, copied files, images) and shows
Omarchy's two-pane picker: a search line at the top, up to 50 matching entries on the left,
and a full preview of the selected entry on the right (wrapped text, the file path list, or the
image). The same entry copied again moves to the top. History holds 500 entries.

| Key | Action (same as upstream) |
|---|---|
| typing / ⌫ | filter (search covers text, file names, and "image screenshot <mime> <time>") |
| ↑ ↓ | move, wraps around; PgUp/PgDn move 6; Home/End jump to first/last |
| Return | paste into the app that was focused before (sets clipboard + ⌘V) |
| Shift+Return | copy only |
| Option+Return | open (file → default app, http/mailto link → browser, image → Preview "New from Clipboard") |
| Delete (fn+⌫ on laptops) | remove the selected entry |
| Shift+Delete | "Delete clipboard history?" confirmation (Delete / Cancel, Cancel preselected) |
| Esc | clear the search, or close if the search is empty |
| mouse | hover selects only after the pointer actually moves (upstream PointerMoveGate); click pastes; click outside the card closes |

Empty state: glyph `󰅌` with "Clipboard is empty", or `No matches for "<query>"`.
Rows: image previews as a 34 px square thumbnail; image/file rows dimmed to 0.72 opacity, as upstream.
Image labels: "Screenshot from Monday 14:03" (PNG) / "Image from …" (others); files: the file name, or "N files".

## Omarchy → macOS mapping
| Omarchy | macOS port |
|---|---|
| `wl-paste --watch capture.sh` (text + image/png watchers) | `hs.pasteboard.watcher` (falls back to polling `changeCount` every 2 s on old Hammerspoon) |
| `capture.sh` priority image → text | files (`NSFilenamesPboardType` / `public.file-url`) → text → image. Text wins over an image unless the text is just a URL (browser "Copy Image"). This stops Office/Excel copies, which also carry a picture, from being saved as images. |
| `x-kde-passwordManagerHint`, `CLIPBOARD_STATE=sensitive` | nspasteboard.org markers (`org.nspasteboard.ConcealedType`, `TransientType`, `AutoGeneratedType`, 1Password/KeeWeb/TypeIt4Me markers) and any `*citrix*` pasteboard type |
| `~/.local/state/omarchy/clipboard-history.json` + `clipboard-images/*.png` | **in memory only** (Lua tables + `hs.image`; previews are in-memory PNG data URLs) |
| `ClipboardHistory.js` (normalize, dedupe, 8192-char display cap cut at a line break, search, preview text) | ported 1:1 in Lua (`textEntry`, `addEntry`, `capText`, `displayRows`) |
| `OverlayWindow` layer-shell + scrim + `BorderSurface` card 875×600 | full-screen transparent borderless `hs.webview` (modalPanel level) with a scrim and a centred card, `min(875, screen-40) × min(600, screen-40)` |
| `omarchy-clipboard-paste-text --shift-insert` / `paste-file` | write to `NSPasteboard` (text, `NSURL`s for files, `hs.image` for images), refocus the previous window, `⌘V` via `hs.eventtap` (Accessibility is already granted) |
| `--copy-only` | same write, no keystroke |
| `omarchy-clipboard-open` | `/usr/bin/open <paths>` (argument list, no shell), `hs.urlevent.openURL`, Preview + ⌘N |
| theme `menu` tokens | background → `background`, text → `foreground`, border → `accent` (2 px, square corners like the other omarchy-mac overlays), selectedBackground → `selection`, selectedText → `accent`, divider → `accent` at 28 % |
| `Style.font.menuFamily` | JetBrainsMono Nerd Font (search 20 px, rows/preview 16 px, empty glyph 48 px) |

## Privacy and safety
- Clipboard contents never go into logs, files or `omniwmctl shell set`. The module publishes no
  OmniShell var (no bar presence). The log only ever records counts and sizes.
- Copies are ignored while **Citrix Viewer** (`com.citrix.receiver.icaviewer.mac`) or a password
  manager (1Password, Bitwarden, KeePassXC, Apple Passwords, Keychain Access, Dashlane, LastPass,
  Enpass, Strongbox, NordPass, Proton Pass) is frontmost, **and for 3 s after one of them was
  activated or deactivated**. This covers Citrix syncing its clipboard when focus leaves it.
- URL actions only open, close or ask to clear (the clear still needs confirmation in the
  overlay). Paste, copy, remove and open come only from the overlay page and are checked
  against the in-memory history by entry id. No action takes an argument.
- Image previews of copied *files* are decoded in memory (`hs.image.imageFromPath`, files ≤ 40 MB,
  60 cached). No thumbnails are written to disk.
- Single copies over 8 MB are skipped. At most 20 images are kept (oldest dropped first).

## Hotkeys to bind (`~/.config/omarchy-mac/bindings.toml`)
| Omarchy chord | Action |
|---|---|
| `SUPER CTRL V` | `clipboard.toggle` |

Example: `hs = "clipboard.toggle"` on that chord. Maccy is also installed and keeps its own
history. Either quit Maccy or leave its shortcut on a different chord.

## Bar placement
None. Upstream is overlay-only (`kinds: ["overlay"]`), so there is no widget.

## Requires
Nothing new: Hammerspoon built-ins only (`hs.pasteboard`, `hs.webview`, `hs.eventtap`, `hs.image`).

## Gaps (honest)
1. **No persistence.** Upstream keeps history in a JSON file and images on disk across restarts.
   The safety rules forbid writing clipboard contents to files, so history is cleared when
   Hammerspoon reloads or restarts.
2. **Image limit.** Upstream keeps images as files up to the 500-entry limit. Here at most 20
   images stay in RAM.
3. **Open on plain text** (Option+Return) only works for single http(s)/mailto links. Upstream's
   `omarchy-clipboard-open` source was not in the plugin and a text-to-editor open would need a temp
   file. Otherwise it shows "Nothing to open". Opening an image goes through the clipboard, so
   that image also moves to the top of the history.
4. **Paste keystroke** is ⌘V, not Shift+Insert (the macOS equivalent).
5. **Strings are English only.** Upstream strings come from `Commons.I18n`. The English texts
   ("Search clipboard…", "Clipboard is empty", `No matches for "%1"`, "Delete clipboard history?",
   "Delete", "Cancel") are best guesses at the catalogue. The order and default of the confirm
   buttons are guesses too; the port preselects the safe choice.
6. Search is case-insensitive for ASCII only (Lua `string.lower`).
7. Universal Clipboard / remote copies are recorded like local ones. Upstream has no equivalent.

## Test steps
1. Install, reload Hammerspoon, bind `SUPER CTRL V` → `clipboard.toggle`, or run
   `open "hammerspoon://omarchy?a=clipboard.toggle"`.
2. Copy three different texts in TextEdit. Open the overlay and check the newest is at the top. Copy the
   first one again and check it moves to the top without being duplicated.
3. Type to filter. Check that ↑/↓ wrap, PgUp/PgDn/Home/End move, and the right pane shows the full text.
4. Return pastes into TextEdit. Shift+Return only copies (⌘V afterwards pastes it).
5. Copy two files in Finder: the row reads "2 files". Copy one PNG file: it shows a thumbnail and the file name.
   Option+Return opens it. Paste into a Finder window copies the files.
6. ⌘⇧⌃4 screenshot to clipboard: the row reads "Screenshot from <Day HH:MM>" with an image preview.
   Return pastes it into Preview/Notes.
7. fn+⌫ removes the selected row. Shift+fn+⌫ asks first; Cancel keeps the history, Delete empties it
   ("Clipboard is empty").
8. Privacy: copy in Citrix Viewer and in 1Password/Passwords. Neither appears. Check that
   `~/.local/state/omarchy-mac/hs.log` contains no copied text.
9. Esc with a query clears it; Esc again (or clicking the scrim) closes and focus returns.
